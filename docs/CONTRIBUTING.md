# Cycle de contribution

## Principe

Une contribution est une proposition publique, jamais une validation automatique. Le formulaire `/contribuer` prépare un objet JSON portable puis, au choix, le copie, le télécharge ou ouvre une issue GitHub préremplie.

Aucune donnée n'est envoyée pendant la saisie. L'ouverture du lien GitHub ne publie encore rien : la personne doit confirmer la création de l'issue sur GitHub.

## Contenu minimal

Chaque proposition contient :

- un type : source, argument ou correction ;
- un thème principal ;
- un titre et un résumé ;
- une justification et les éléments restant à vérifier ;
- une objection sérieuse ;
- des limites éventuelles ;
- une source web lorsqu'elle est déjà connue.

Le schéma impose aussi l'acceptation de la publication publique et de l'interdiction du profilage ou ciblage politique individuel fondé sur des données sensibles.

## Relecture

Une issue proposée suit quatre contrôles avant intégration :

1. vérifier la source, son auteur, sa date et son contexte ;
2. séparer observation, interprétation et conclusion normative ;
3. instruire l'objection et les éléments contradictoires ;
4. vérifier les droits de publication et les garde-fous éthiques.

L'historique de l'issue, de la pull request et des commits constitue le premier journal des changements. Une interface éditoriale et des rôles dédiés ne seront ajoutés qu'après observation de ce flux réel.
